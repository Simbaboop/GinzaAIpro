# Operational Knowledge Graph

## Purpose

The Operational Knowledge Graph represents relationships between operational entities, evidence, events, memory, assessments, decisions, executions, outcomes, and learning.

It provides the structural context that allows GinzaAIpro to reason over connected operational reality rather than isolated records.

---

## Responsibilities

The Operational Knowledge Graph owns:

- operational nodes
- operational edges
- graph relationships
- relationship traversal
- path discovery
- future impact analysis
- future causal chain analysis

---

## Non-Responsibilities

The Operational Knowledge Graph does not own:

- evidence capture
- runtime execution
- signal propagation
- memory storage
- health scoring
- cognition
- governance
- UI rendering

Those belong to Operational Evidence, Runtime, Operational Nervous System, Operational Memory, Operational Health, Operational Cognition, Governance, or Experience.

---

## Core Concepts

### Node

A node represents an operational entity.

Examples:

- Customer
- Lead
- Invoice
- Appointment
- Employee
- Asset
- Evidence
- Assessment
- Decision
- Execution
- Outcome

---

### Edge

An edge represents a relationship between two nodes.

Examples:

- GENERATED
- CAUSED
- RELATED_TO
- PRODUCED
- EXECUTED
- VERIFIED
- LEARNED_FROM
